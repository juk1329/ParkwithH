# ParkwithH

**목적지 주차장에 다다르면 어디에 주차하면 되는지, 차에서 차로 전해지는 주차 가능 구역 안내**

붐비는 주차장 입구에서 운전자가 알 수 있는 것은 많아야 "전체 잔여 몇 대"입니다. 어느 층, 어느 구역에 주차 가능 구역이 있는지는 직접 찾아봐야 합니다. ParkwithH는 차량에 설치되어 기어·속도·도어·내비 목적지와 같은 차량에 대한 정보만으로 주차가 가능한 자리를 추적하여 **주차장을 빠져나가는 차의 자리를 들어오는 차에게 넘겨줍니다.** 이 앱은 운전자의 직접적인 조작을 필요로 하지 않으며 음성과 알림을 위주로 정보를 전달합니다.

> 모든 동작은 Pleos Connect 에뮬레이터에서 확인해 보실 수 있습니다.

| 항목 | 내용 |
|---|---|
| APK | [`apk/이거어디까지내려가는거에요_ParkwithH_release.apk`](apk/) (release 서명, 약 27MB) |
| 시연 영상 | [`demo/ParkwithH_demo.mp4`](demo/ParkwithH_demo.mp4) (2분 33초, 에뮬레이터 2대의 실제 동작 녹화. 기어·속도·위치·경로는 시험 도구로 넣었고, 목록을 채우는 다른 차들은 가상 차량입니다) |
| 기본 시연 | [에뮬레이터 2대 + 시연 콘솔](#2-차량-2대로-보기-기본-시연): 나가는 차의 자리가 서버를 거쳐 들어오는 차의 목록에 뜨고, 주차장에 도착하면 가는 구역이 확정되고, 주차로 사라지는 전체 장면, 약 5분 |
| 저자원 환경 | [에뮬레이터 1대 + APK만으로 데모 모드](#3-저자원-환경-한-대로-보기-데모-모드): 서버 없이 다른 차를 앱이 흉내 냅니다, 약 3분 |

## Pain point

**운전자.** 대형 주차장에서는 빈자리를 찾는 일이 운전자의 부담으로 다가옵니다. 입구 전광판이 "잔여 37대"라고 알려 줘도 그 37대가 지하 몇 층 어느 쪽인지는 알 수 없고, 앞차를 따라 같은 구역으로 들어갔다가 함께 헛걸음하기도 합니다. 주행 중에는 휴대폰을 볼 수도 없습니다.

**주차장.** 층·구역 단위로 안내하려면 면마다 센서를 달고 유도 전광판을 세우거나 안내 인력을 배치해야 합니다. 그럴 여력이 없는 주차장에서는 이 문제가 풀리지 않은 채 남습니다.

**ParkwithH의 답.** 층·구역 정보를 만들 수 있는 것은 그 자리에 주차되어 있던 차입니다. 차는 자기가 주차했다는 것(후진 뒤 P)과 나간다는 것(P에서 D, 그리고 이동)을 기어 변경 정보를 통해서 알 수 있습니다. 이 사실을 그 주차장으로 향하는 다른 차에 넘기면, 설비도 인력도 없이 층·구역 안내가 생깁니다.

## 무엇을 하는가

```
나가는 차 A                 서버                 들어오는 차 B                  뒤따르는 차 C
─────────────────────────────────────────────────────────────────────────────────────────────
기어 P → D        곧 1곳 ──▶ 목록 갱신
15m 이동·이탈     1곳 ─────▶ 목록 갱신
                                      ◀── 100m 앞 ── 🔊 "주차 가능 구역이에요.
                                                        지하 2층 B구역 1곳…"
                             가는 중 ◀───────────── 추천 구역을 자동으로 알림
                                                                                 100m 앞 ──▶ 🔊 B가 가는 구역은
                                                                                              "앞차가 가는 중",
                                                                                              다른 구역을 추천
                             확정 ◀──────────────── 주차장 도착 🔊 "…으로 확정했어요"
                             (자리가 없으면 확정 취소 ◀── "자리 없어요" → 다른 구역으로 다시 확정)
                             1곳 감소 ◀──────────── 후진 → P, [맞아요] 한 번
```

| 순간 | 앱이 하는 일 | 운전자 조작 |
|---|---|---|
| 내비 목적지를 정함 | 목적지 주변 주차장을 찾아 "코엑스 주차장, 약 2,100면 규모예요"라고 한 번 말합니다. 미리 수집한 공개 정보 데이터를 통해 안내합니다 | 없음 |
| 가는 길 (100m 밖) | 그 주차장의 목록을 조용히 갱신합니다. 말하지 않습니다 | 없음 |
| **주차장 100m 앞** | 서버에서 방금 받은 **층별 주차 가능 구역**을 음성과 화면 상단 배너 알림으로 한 번 알립니다. 다른 차가 향하지 않는 구역을 골라 "지하 2층 B구역으로 간다고 알렸어요"라고 말합니다(가는 중) | 없음. 다른 구역으로 갈 때만 구역 이름이나 "취소"를 말합니다 |
| **주차장 도착** | 가는 중이던 구역을 **확정**으로 바꾸고 "주차장에 도착했어요. 지하 2층 B구역으로 확정했어요"라고 말합니다. 다른 차의 목록에는 "앞차 1대 확정"으로 보입니다 | 없음 |
| 주차장 안에서 찾는 동안 | 변동만 말합니다. "지하 1층 C구역에서 방금 1대 나갔어요", "가시려던 지하 2층 B구역에 다른 차가 먼저 주차했어요. 지하 1층 C구역에 1곳 있어요" | 없음 |
| **확정한 구역에 자리가 없을 때** | 확정 90초 뒤에도 주차하지 않았으면 "지하 2층 B구역에 자리가 없으면 '자리 없어요'라고 말씀해 주세요"라고 한 번 묻습니다. 답을 들으면 확정을 바로 취소하고 그 구역의 지난 출차 소식을 목록에서 지운 뒤 "지하 2층 B구역 확정을 취소했어요. 지하 3층 C구역에 1곳 있어요. 그쪽으로 확정했어요"라고 안내합니다 | "자리 없어요" 한마디. 정차(P) 중이면 [자리 없어요] 버튼 |
| 후진 → P | "지하 2층 B구역에 내 차 위치 저장" 알림을 띄웁니다 | **[맞아요] 한 번.** 앱을 열지 않습니다 |
| 주차 확정 | 목록에서 그 구역 1곳과 "확정"이 사라지고, 내 차 위치가 저장됩니다 | 없음 |
| 다시 출발 | 기어가 P를 벗어나면 "곧 1곳", 15m 이상 움직이거나 주차장을 벗어나면 "1곳"이 다음 차의 목록에 생깁니다 | 없음 |

앱 화면은 보조 수단입니다. 주행 중에는 버튼 없는 카드 한 장(층 띠, 구역 글자, 수량)만 보이고, 정차(P)했을 때만 입력 화면이 나옵니다.

### 목록의 숫자가 뜻하는 것

| 표시 | 뜻 |
|---|---|
| **N곳** | 그 구역에서 최근 10분 안에 출차가 확정된 앱 차량 수에서, 그 뒤 그 구역에 주차한 앱 차량 수를 뺀 값. 출차 확정은 주차했던 차가 P를 벗어난 뒤 15m 이상 이동하거나 주차장을 벗어났을 때입니다. 이동 거리는 차량 속도 신호로 구하므로 지하에서도 판단할 수 있습니다 |
| **곧 N곳** | 주차했던 차의 기어가 P에서 R·D로 바뀐 직후. 15m 이동 전에 P로 돌아오면 취소됩니다(자리 정렬이나 잠깐 뺐다 넣은 경우) |
| **앞차 N대 가는 중** | 주차장 100m 앞에서 그 구역으로 간다고 알린 다른 접근 차량 수. 10분 뒤 사라집니다 |
| **앞차 N대 확정** | 주차장에 도착해 그 구역으로 가는 것이 확정된 다른 차량 수. 주차하면 바로 해제되고, 자리가 없어 취소하면 그 구역의 지난 출차 소식도 함께 지워집니다 |
| 1분 전 | 가장 최근 출차로부터 지난 시간 |

"확정"은 자리 예약이 아니라 "이 차가 그 구역으로 들어왔다"는 알림입니다. 목록 아래에는 항상 **"앱 차량의 출차 기준이에요. 자리 보장은 아니에요."**가 붙습니다. 앱은 이 앱을 쓰는 차만 볼 수 있어서, 주차장 전체의 잔여 면수를 말하지 않습니다.

### 한계와 해결 방법

- **사용자가 충분하지 않은 경우.** 미리 수집한 공개 데이터(주차장 12,214곳의 이름·위치·등록 면수)로 목적지 주변 주차장의 정보를 전달하고 내 차 위치를 저장해 줍니다. 다른 사용자가 없어도 쓸모가 있는 기능으로 사용과 가입을 유도합니다.
- **사용자 유치 전략: 받으려면 주게 되는 구조.** 안내를 받고 주차한 운전자가 [맞아요] 한 번으로 자기 구역을 확인하면, 그 차가 나갈 때 그 구역이 다음 차에게 전해집니다. 따로 "공유" 버튼을 누르는 사람이 없어도 정보가 돕니다.
- **필요한 참여 차량 수.** 만차인 주차장에서 평균 2시간 주차한다고 가정하면, 동시에 주차한 앱 차량 12대에서 10분당 평균 출차 소식 1건을 기대할 수 있습니다. 가정에 따른 계산이며 현장 실측값이 아닙니다. 소식이 없는 시간대와 구역이 생길 수 있고, 구역마다 소식을 얻으려면 그만큼 더 필요합니다.
- **층·구역 입력.** 층·구역은 자동으로 측정하지 않고 운전자가 한 번 확인한 값을 씁니다(알림 버튼 한 번, 음성, 키패드). 한 번 확인한 주차장에서는 다음부터 지난 구역을 먼저 제안합니다.
- **주차장 운영사.** 센서 없이 구역별 출차·주차 흐름을 보는 시연용 대시보드를 함께 제공합니다. 유도 설비가 이미 있는 곳은 그 데이터와 연동하는 쪽이 맞습니다.
- **시연용 서버.** 포함된 서버는 이 PC 안에서 도는 시연용입니다. 인증이 없으므로 인터넷에 그대로 공개하는 용도가 아닙니다.

### 향후 과제

- **주거 시설 주차장.** 현재는 개인정보 우려로 주거 시설로 보이는 주차장은 취급하지 않습니다(세션을 만들지 않고 아무것도 보내지 않습니다). 집 위치가 드러나지 않는 방식으로 주거 시설 주차장에서도 쓸 수 있는 기능을 고려해야 합니다.
- **앱을 쓰지 않는 차의 주차.** 출차 소식이 있어도 그 사이 앱을 쓰지 않는 차가 들어갔을 수 있습니다. 지금은 경과 시간 표시와 "자리 없어요" 취소로 보완합니다. 향후 차량에 내재된 여러 센서의 정보까지 받아올 수 있다면, 그 근처에 있는 이 앱을 쓰는 현대자동차 차량을 통해 이러한 정보까지 갱신할 수 있을 것입니다.

## 실행 방법

화면이 있는 일반 PC·노트북(Windows, macOS, Linux)을 기준으로 씁니다. 화면이 없는 Linux 서버에서 실행하는 방법은 [4절](#4-화면이-없는-linux-서버에서-실행하기)에 있습니다.

### 1. 에뮬레이터 준비 (처음 한 번)

Pleos 공식 문서 [에뮬레이터 설치](https://document.pleos.ai/docs/connect/guide/getting-started/application-development/setup-connect-sdk-emulator)와 [에뮬레이터 설정](https://document.pleos.ai/docs/connect/guide/getting-started/application-development/configure-pleos-connect-emulator)을 요약했습니다. 공식 문서는 **그래픽 카드가 필수**라고 안내합니다.

1. Android Studio를 설치합니다.
2. **Tools → SDK Manager → SDK Update Sites** 탭에서 **+** 를 누르고 아래를 추가합니다.
   - Name: `Pleos Connect System Image`
   - URL (Windows·Linux): `https://nexus-playground.pleos.ai/repository/raw-releases/connect-avd/2.x/crp-sys-img.xml`
   - URL (Mac): `https://nexus-playground.pleos.ai/repository/raw-releases/connect-avd/2.x/crp-arm64-sys-img.xml`
3. **SDK Platforms** 탭에서 **Show Package Details**를 켜고, Android API Level 34의 **Pleos Connect system Image**를 체크해 설치한 뒤 Android Studio를 다시 시작합니다.
4. **Tools → Device Manager → Create device**에서 가상 기기를 만듭니다.
   - Form Factor **Automotive** → **Pleos Connect v2.1.0**
   - **Advanced Settings**: Startup의 Default boot를 **Cold**로, RAM을 **4 GB**로 설정합니다.
   - 시스템 이미지: API 34의 **Pleos Connect v2.1.0 APIs**
5. **같은 가상 기기를 하나 더 만듭니다.** 차량 A와 차량 B로 씁니다. 4번을 한 번 더 하거나, Device Manager에서 만든 기기의 **⋮ → Duplicate**를 고릅니다.
6. Device Manager에서 실행합니다. **Cold boot가 아니면 차량 신호(기어, 도어)가 앱에 들어오지 않습니다.**

아래 명령은 `adb`가 PATH에 있다고 가정합니다. 없다면 Android SDK의 `platform-tools` 폴더를 PATH에 추가하세요. 시연 콘솔은 아래 기본 위치에서 `adb`를 스스로 찾습니다.

| OS | `platform-tools` 기본 위치 |
|---|---|
| Windows | `%LOCALAPPDATA%\Android\Sdk\platform-tools` |
| macOS | `~/Library/Android/sdk/platform-tools` |
| Linux | `~/Android/Sdk/platform-tools` |

### 2. 차량 2대로 보기 (기본 시연)

이 앱의 핵심 장면입니다. 차량 A가 코엑스 주차장 지하 2층 B구역에서 나가면, 내비 화면만 띄워 둔 차량 B가 주차장 100m 앞에서 층별 주차 가능 구역을 음성과 알림으로 받고, 앞차가 가는 구역을 피해 갈 곳을 알린 뒤, 주차장에 도착하면 그 구역이 확정되고, 버튼 한 번으로 주차합니다. 에뮬레이터 2대가 함께 돌아가므로 메모리가 넉넉해야 합니다(에뮬레이터당 RAM 4 GB).

**시연 콘솔**(`tools/demo_console.py`)이 서버를 켜고 두 차를 준비한 뒤, 브라우저 한 화면에서 두 차의 기어와 위치를 순서대로 바꿉니다. 명령을 입력할 일이 없습니다.

1. 서버 패키지를 설치합니다(처음 한 번). Python 3.10 이상이 필요합니다.
   ```bash
   pip install -r server/requirements.txt
   ```
2. 두 가상 기기를 모두 실행하고, 창을 나란히 둡니다.
3. 저장소 루트에서 시연 콘솔을 실행합니다.
   ```bash
   python tools/demo_console.py
   ```
   콘솔이 하는 일:
   - 부팅을 마친 에뮬레이터 2대를 기다립니다. 포트 번호가 작은 쪽(보통 `emulator-5554`)이 차량 A, 다른 쪽이 차량 B입니다.
   - 앱이 없으면 `apk/`의 release APK를 설치합니다. 다시 설치하려면 `--install`을 붙이세요.
   - 첫 실행 때 묻는 권한(위치, 알림, Pleos 위치, 속도)을 미리 허용합니다.
   - Virtual Console을 차량 A는 `http://127.0.0.1:8088/`, 차량 B는 `http://127.0.0.1:8089/`에 연결합니다.
   - 서버를 `127.0.0.1:8787`에서 켭니다. 이미 켜져 있으면 그대로 씁니다. 예전 버전의 서버가 켜져 있으면 알려 주고 멈춥니다.
   - 두 차의 앱을 **서버 모드**로 엽니다(`am start ... --es mode server`).
   - 두 차를 주차장 밖에 P로 세우고 서버 기록을 지운 뒤, 브라우저로 `http://127.0.0.1:8790/`을 엽니다.
4. 두 차 화면에서 **동의하고 시작**을 누릅니다. 콘솔에 "A차 준비됨 B차 준비됨"이 나오면 시작합니다.
5. 콘솔의 버튼을 위에서부터 누릅니다.

| 순서 | 콘솔 버튼 | 에뮬레이터 화면에서 할 일 | 보이고 들리는 것 |
|---|---|---|---|
| 1 | **A차 주차 (후진 → P)** | A차 화면 위 "내 차 위치를 저장할까요?" 배너에서 **층·구역 입력** → **B2** → **B** | 콘솔 목록에 지하 2층 B구역 "주차 중 1대" |
| 2 | **B차 출발 (기어 D)** | 누르기 전에 B차 화면의 ParkwithH에서 **1. 코엑스로 안내 시작** | B차 내비가 코엑스 주차장으로 안내하고 "코엑스 주차장, 약 2,100면 규모예요" |
| 3 | **A차 출차 (기어 D → 주차장 밖)** | 없음 | 목록에 지하 2층 B구역 **곧 1곳**, 약 5초 뒤 **1곳**. B차는 멀리 있어 아무 말도 하지 않습니다 |
| 4 | **가상 차량 넣기** | 없음 | 목록에 지하 1층 A구역 1곳 "가는 중 1대", 지하 3층 C구역 1곳이 생깁니다. 에뮬레이터가 아닌 차들의 이벤트를 콘솔이 서버에 대신 보낸 것입니다 |
| 5 | **B차 위치를 100m 앞으로** | 없음 | 앱을 열지 않은 B차에 "주차 가능 구역 · 코엑스 주차장" 배너와 음성. "지하 2층 B구역 1곳, 지하 3층 C구역 1곳. 지하 1층 A구역은 앞차가 가는 중이에요." 이어서 "지하 2층 B구역으로 간다고 알렸어요." 목록의 지하 2층 B구역에 "가는 중 1대" |

- **가상 차량:** 에뮬레이터 2대로는 여러 구역이 있는 목록과 "앞차"를 만들 수 없어서 넣었습니다. 내용은 `tools/demo_console.py`에 고정돼 있고, 콘솔 화면에 "가상 차량"이라고 표시합니다. 콘솔 오른쪽의 **B차가 가던 지하 2층 B구역에 먼저 주차** 버튼을 5번과 7번 사이에 누르면, B차가 "가시려던 지하 2층 B구역에 다른 차가 먼저 주차했어요. 지하 3층 C구역에 1곳 있어요."라고 말하고 갈 곳을 옮깁니다.
- **3번에서 위치를 옮기는 이유:** 속도 신호가 있는 차는 15m 이상 움직이거나 주차장을 벗어나야 출차로 확정합니다. 잠깐 D에 넣었다가 다시 P로 돌아온 차를 출차로 잘못 알리지 않기 위해서입니다. Virtual Console 화면에는 주행 장치가 없으므로 위치를 옮겨 주차장 이탈을 만듭니다.
- **5번의 위치:** 코엑스 주차장 좌표에서 380m 떨어진 점입니다. 카탈로그가 이 주차장의 범위로 잡은 반경 300m의 80m 앞이라, 앱이 "100m 앞"으로 판단합니다.
- **자리가 없을 때:** 6번 뒤 90초 동안 주차하지 않으면 B차가 "지하 2층 B구역에 자리가 없으면 '자리 없어요'라고 말씀해 주세요"라고 한 번 묻습니다. 마이크로 "자리 없어요"라고 답하면 "지하 2층 B구역 확정을 취소했어요. 지하 3층 C구역에 1곳 있어요. 그쪽으로 확정했어요."라고 말하고, 목록에서 지하 2층 B구역의 1곳이 지워집니다. 기어가 P일 때는 알림이나 앱의 구역 선택 화면에 있는 **자리 없어요** 버튼으로도 됩니다.
- **음성으로 바꾸기:** 마이크가 연결돼 있으면 5번의 안내 직후 "지하 3층 C구역"이나 "취소"라고 말해 갈 곳을 바꿀 수 있습니다. 에뮬레이터 **Extended Controls → Microphone**에서 호스트 오디오 입력을 켜야 합니다.
- **앱 화면으로 보기:** 5번 뒤 B차에서 ParkwithH를 열면 주행 카드에 같은 목록이 층별로 보입니다. 주행 중이라 버튼은 없습니다.
- **다시 하기:** 콘솔의 **처음부터 다시**를 누릅니다. 두 번째부터는 앱이 지난 구역을 기억해서, 1번에서 "지하 2층 B구역에 내 차 위치 저장" 배너가 뜹니다. **맞아요**를 누르세요. B차의 경로도 남아 있어 2번의 앱 버튼은 다시 누르지 않아도 됩니다.
- **운영사 대시보드:** 콘솔의 링크나 `http://127.0.0.1:8787/v1/lots/59446-29391-00005-00-1/dashboard`에서 층별 목록과 원시 이벤트 로그를 봅니다.
- 콘솔의 차량 카드로 기어(P·R·N·D)와 위치(주차장 안·100m 앞·밖)를 하나씩 바꿀 수도 있습니다. Virtual Console 페이지를 함께 열어 써도 됩니다.
- 끝낼 때는 터미널에서 **Ctrl+C**를 누릅니다. 콘솔이 켠 서버도 함께 꺼집니다.
- 콘솔은 이 PC의 `127.0.0.1`에서만 열리고, 정해진 버튼 동작만 받습니다.

### 3. 저자원 환경: 한 대로 보기 (데모 모드)

에뮬레이터 1대와 APK만으로, 서버 없이 흐름을 봅니다. 처음 설치하면 데모 모드가 켜져 있습니다. 앱이 다른 차량과 서버를 흉내 내며, 서버로 아무것도 보내지 않습니다. 화면에는 항상 "데모 모드"라고 표시합니다. 주차장 이름과 면수는 공공 데이터의 실제 값이고, 다른 차량과 구역 이름은 예시입니다.

저장소 루트에서 설치하고 Virtual Console을 연결합니다.

```bash
adb install -r apk/이거어디까지내려가는거에요_ParkwithH_release.apk
adb forward tcp:8088 tcp:8088
```

- 브라우저에서 `http://127.0.0.1:8088/`을 열면 Virtual Console(차량 신호 조작 화면)이 나옵니다.
- **Emulation Controls** 왼쪽의 Domain에서 **Motion**을 고르면 기어(P·R·N·D)를 바꿀 수 있습니다. 도어는 **Convenience**에 있습니다.
- 에뮬레이터를 다시 켜면 `adb forward`도 다시 실행해야 합니다.

시작 전에 Virtual Console에서 기어를 **P**로 둡니다. 기어가 P가 아니면 앱은 주행 카드만 보여 주고 버튼을 숨깁니다.

| 순서 | 할 일 | 보이고 들리는 것 |
|---|---|---|
| 1 | 화면 아래 가운데의 **네모 4개 아이콘** → **앱** 탭 → **ParkwithH**(P 아이콘)를 열고 **동의하고 시작**을 누릅니다 | 권한 창이 3번 뜹니다. 위치는 **앱 사용 중에만 허용**, 알림과 "알 수 없는 작업 실행"은 **허용**을 누르세요. "알 수 없는 작업"은 Pleos 위치(FusedLocation) 권한이며, 에뮬레이터가 이름을 이렇게 표시합니다 |
| 2 | **1. 코엑스로 안내 시작** | 내비가 앞으로 나오고 코엑스 주차장 경로가 잡힙니다. 곧 "코엑스 주차장, 약 2,100면 규모예요"가 음성과 배너로 나옵니다 |
| 3 | 화면 아래에 생긴 **P 아이콘**(또는 1번의 앱 목록)으로 앱에 돌아가 **2. 주차장 100m 앞 도착 (가상 위치)**를 누르고, 화면 아래의 **화살표 아이콘**(내비게이션)으로 내비 화면에 돌아갑니다 | "코엑스 주차장 주차 가능 구역이에요. 지하 2층 B구역 2곳, 지하 1층 C구역 1곳. 지하 1층 A구역은 앞차가 가는 중이에요." 이어서 "지하 2층 B구역으로 간다고 알렸어요. 다른 구역이면 말씀해 주세요." 같은 내용이 배너로도 뜹니다 |
| 4 | 앱에서 **3. 주차장 도착 (가상 위치)**를 누르고 내비 화면으로 돌아갑니다 | "주차장에 도착했어요. 지하 2층 B구역으로 확정했어요." 앱을 열면 주행 카드에 "확정한 내 구역"이 보입니다 |
| 5 | 앱에서 **4. 10초 뒤 다른 차 출차**를 누르고 내비 화면으로 돌아갑니다 | 10초 뒤 "지하 2층 B구역에서 곧 나갈 차가 있어요", 6초 뒤 "지하 2층 B구역에서 방금 1대 나갔어요". 앱을 열지 않은 상태입니다 |
| 6 | Virtual Console에서 기어를 **D**, **R**, 2초 뒤 **P**로 바꿉니다 | 몇 초 뒤 "지하 2층 B구역에 내 차 위치 저장" 배너가 뜹니다. **맞아요**를 누르면 앱을 열지 않고 저장됩니다. 앱을 열면 "내 차 위치"에 지하 2층 B구역이 보입니다 |

- 3번 뒤에는 앱 화면에 층별 목록이 생겨 데모 버튼이 아래로 밀립니다. 화면을 위로 밀어 올리면 버튼이 보입니다.
- 3번과 4번은 에뮬레이터의 차가 실제로 달릴 수 없어 둔 버튼입니다. 차 위치를 주차장 80m 앞과 주차장 안으로 가정하고, 다른 차들의 출차와 앞차를 앱 안에서 만들어 냅니다.
- 3번 뒤 앱을 열면 층별 목록이 보입니다. 정차(P) 상태에서는 목록의 구역을 눌러 갈 곳을 바꾸거나, 목록 아래의 **지하 2층 B구역에 자리 없어요**를 눌러 확정을 취소하고 다른 구역으로 옮길 수 있습니다.
- 마이크가 연결돼 있으면 3번에서 다른 구역 이름을, 6번에서 "네"를 말해도 됩니다. 에뮬레이터 **Extended Controls → Microphone**에서 호스트 오디오 입력을 켜야 합니다.
- 규모 안내는 목적지마다 한 번만 말합니다. 처음 상태로 다시 보려면 `adb uninstall app.parkrelay` 후 다시 설치하세요.
- 소리가 나지 않아도 같은 문장이 배너로 보입니다.
- 시연 콘솔을 쓴 기기는 서버 모드로 바뀌어 있습니다. 앱의 **설정 → 데모 모드 켜기**로 되돌립니다.

### 4. 화면이 없는 Linux 서버에서 실행하기

개발에 쓴 PC가 이 방식입니다. `tools/emu.sh`가 가상 디스플레이를 만들고 에뮬레이터를 Cold Boot로 켭니다. GPU가 없어도 되도록 기본은 소프트웨어 렌더링(`swiftshader_indirect`)입니다. 가상 디스플레이에서는 두 차의 창을 절반 크기로 나란히 놓아, 원격 화면 하나에 두 차가 함께 보입니다.

```bash
# emulator와 adb가 PATH에 있어야 합니다. 가상 기기 이름은 기본 Pleos_Veh1, Pleos_Veh2이며 AVD_1, AVD_2로 바꿀 수 있습니다.
tools/emu.sh xvfb                         # 가상 디스플레이 :77 생성
tools/emu.sh boot 1                       # 차량 A: emulator-5554, 왼쪽
tools/emu.sh boot 2                       # 차량 B: emulator-5556, 오른쪽
python tools/demo_console.py --no-browser # 2절의 시연 콘솔
EMU_GPU=host tools/emu.sh boot 1          # GPU가 있으면 하드웨어 렌더링
tools/emu.sh stop 1                       # 저장소를 동기화하고 끔
```

- **화면 보기:** NoMachine, VNC 같은 원격 데스크톱으로 디스플레이 `:77`에 접속합니다.
- **시연 콘솔과 대시보드:** 서버에 브라우저가 없으면, 사용하는 노트북에서 SSH 터널을 연 뒤 노트북 브라우저로 `http://127.0.0.1:8790/`(시연 콘솔)과 `http://127.0.0.1:8787/…`(대시보드)을 엽니다. 콘솔을 쓰면 Virtual Console(8088, 8089)은 열지 않아도 됩니다.
  ```bash
  ssh -N -L 8790:127.0.0.1:8790 -L 8787:127.0.0.1:8787 -L 8088:127.0.0.1:8088 -L 8089:127.0.0.1:8089 <사용자>@<서버 주소>
  ```
- **소리:** `-no-window`로 켜면 소리가 나지 않아서, `tools/emu.sh`는 가상 디스플레이에 창을 띄워 실행합니다. 소리는 서버의 오디오 장치로 나갑니다. 원격 데스크톱이 오디오를 전달하지 않으면 배너로 확인하세요.
- 소프트웨어 렌더링으로 오래 켜 두면 에뮬레이터가 스스로 종료될 때가 있습니다. 앱을 지운 상태에서도 같은 현상이 있었습니다. `tools/emu.sh boot 1`로 다시 켜면 됩니다.

```bash
./gradlew :app:assembleRelease    # 저장소 루트에 keystore.properties가 있으면 서명
```

저장소에 서명 키는 없습니다. `keystore.properties` 형식은 `storeFile`, `storePassword`, `keyAlias`, `keyPassword`입니다. Pleos SDK는 `settings.gradle.kts`에 적힌 공식 저장소에서 받습니다. 디버그 빌드와 release APK는 서명이 달라 서로 덮어 설치할 수 없습니다. 바꿀 때는 `adb uninstall app.parkrelay`를 먼저 실행하세요.

| 런타임 권한 | 위치, 알림, `pleos.car.permission.FUSED_LOCATION`("알 수 없는 작업"으로 표시), `android.car.permission.CAR_SPEED`. 첫 실행 때 묻습니다. 시연 콘솔은 `pm grant`로 미리 허용합니다 |
| 차량 신호 | Virtual Console: `adb forward tcp:8088 tcp:8088` 후 `http://127.0.0.1:8088/`. 시연 콘솔은 같은 페이지를 대신 조작합니다 |
| 위치 | `adb emu geo fix <경도> <위도>`. 에뮬레이터 내비의 자차 위치에는 반영되지 않으므로, 앱은 FusedLocation 수신값으로 100m를 판단합니다 |
| 앱 실행 사용자 | Android user 10 (`adb shell am start --user 10 -n app.parkrelay/.MainActivity`) |
| 패키지 이름 | `app.parkrelay` (개발 초기 이름을 유지했습니다) |
| 서버 | Python 3.10 이상, FastAPI. 에뮬레이터에서는 `10.0.2.2:8787`로 접속 |
| 시연 콘솔 | Python 표준 라이브러리만 사용. `127.0.0.1:8790`. 앱은 `--es mode server`(또는 `demo`)로 열면 그 모드로 바뀝니다 |

| 콘솔이 "예전 버전의 서버"라며 멈춤 | 8787 포트를 쓰는 이전 서버 프로세스를 끄고 다시 실행하세요 |

| 콘솔에 "동의 대기"가 계속 보임 | 그 차 화면에서 **동의하고 시작**을 누르세요. 화면에 앱이 없으면 앱 목록에서 ParkwithH를 여세요 |
| 서버 모드에서 소식이 오지 않음 | 서버가 8787 포트에서 실행 중인지, 두 차 모두 서버 모드인지(앱에 "시연 도구"가 보임), B차가 코엑스로 안내 중인지 확인하세요. 100m 밖에서는 일부러 말하지 않습니다 |
| 출차가 확정되지 않음 | 2절 3번처럼 위치를 주차장 밖으로 옮기세요 |

## 사용한 SDK와 확인 상태

공모전이 안내한 Pleos Connect SDK 가운데 이 문제에 필요한 다섯 가지를 씁니다. 버전은 Pleos Connect SDK 릴리스 노트(2026-10-19)의 배포 버전입니다. 아래 확인 결과는 에뮬레이터에서 앱이 화면에 없는 상태로 직접 확인한 것입니다.

| SDK | 버전 | 쓰임 | 에뮬레이터 확인 |
|---|---|---|---|
| Vehicle | 2.3.2 | 운전석·동승석 도어, 운전석 탑승으로 주차와 하차 대기 구분 | 값 수신. 에뮬레이터는 탑승값이 반전되어 보정 |
| NaviHelper | 3.0.5 | 목적지로 주차장 특정, 주차장으로 경로 전달 | 경로 요청, 안내 시작, 목적지 수신 |
| FusedLocation | 1.1.3 | **주차장 100m 앞 판정과 도착(확정) 판정**, 마지막 위치, 세션 이탈·도착 근접 알림 | 위치, ENTER·EXIT 수신. 부팅 후에도 동작 |
| TextToSpeech | 3.3.1 | 주 안내 경로: 층별 목록, 확정, 변동, 주차 확인 (`ON_DEVICE`) | 실제 소리 출력 측정. 오디오 포커스를 잃으면 멈추는 것 확인 |
| SpeechToText | 3.3.1 | 갈 구역 바꾸기, "자리 없어요"로 확정 취소, 층·구역 음성 입력 (`ON_DEVICE`) | 온디바이스 한국어 문장 인식 |

Pleos의 [프로젝트 생성 및 SDK 사용 신청](https://document.pleos.ai/docs/pleos-only/create-my-project) 안내에는 FusedLocation·TextToSpeech·SpeechToText의 Playground 사용 신청이 "준비 중"으로 적혀 있습니다(2026-11-06 확인). 이 앱은 권한 선언과 온디바이스 모드만 쓰므로 Playground 신청이나 앱 등록 없이 동작합니다. 차량 안의 음성을 외부 인식 서비스로 보내지 않습니다.

기어, 속도, 주행 제한 상태는 Pleos 문서의 API 선택 기준에 따라 AAOS 표준 API(`CarPropertyManager`의 `GEAR_SELECTION`·`PERF_VEHICLE_SPEED`, `CarUxRestrictionsManager`)를 씁니다. 주행 제한 여부를 아직 모를 때는 제한 중으로 다룹니다.

**에뮬레이터에서 확인한 범위**

- 화면 상단 배너 알림(헤드업 알림)은 `CATEGORY_NAVIGATION`일 때 표시되는 것을 확인했습니다.
- Suspend는 에뮬레이터로 재현할 수 없어 전원 차단으로 시험했습니다.
- 좁은 창은 창 크기를 강제로 줄여 확인했고, 공식 폼 팩터 테스트 도구로는 아직 시험하지 않았습니다.

## 구조

```
core/     순수 Kotlin. 주차 세션 상태 머신, 접근·선점·확정 상태 머신, 층별 목록과 문구, 주차장 특정, 공유 등급, 음성 문장 파서
app/      Android. 서비스, 신호 소스, 음성, 알림, 화면, 오프라인 큐, 데모 백엔드
server/   FastAPI + SQLite + SSE. 이벤트, 출차 토큰, 선점과 확정, 층별 목록, 운영사 대시보드
tools/    시연 콘솔, 카탈로그 생성, 에뮬레이터 제어, 통합·복구·정책 시험
```

- 주차 세션: `DRIVING → P_TENTATIVE → PARKED → LEAVING → VACATED`. 확정되기 전에는 아무것도 보내지 않습니다.
- 접근: `FAR → NEAR(가는 중) → 진입(확정) → ENDED`. 100m 앞(`위치와 주차장 좌표의 거리 − 카탈로그 반경 ≤ 100m`)에서 서버의 최신 목록을 받아 한 번 알리고, 갈 구역을 `CLAIM` 이벤트로 알립니다. 주차장 범위 안(같은 값 ≤ 0)에 들어오면 `CLAIM_CONFIRM`으로 확정하고, 자리가 없으면 `CLAIM_MISSED`로 취소하면서 그 구역의 지난 출차 소식을 지웁니다.
- 이벤트는 디스크에 먼저 쓰고 보냅니다. 시동이 꺼지거나 지하에서 통신이 끊겨도 다음에 원래 시각 그대로 보냅니다. 오래 끊겼다가 돌아오면 200건씩 나눠 보냅니다.

## 테스트

```bash
./gradlew :core:test                          # 상태 머신, 목록, 추천, 문장 파서: 135건
python -m pytest server/tests tools/tests     # 서버 규칙, 콘솔 보안, 카탈로그: 107건. 원본 공공 CSV가 없으면 4건은 건너뜁니다. ROS 등으로 PYTHONPATH가 잡힌 환경은 env -u PYTHONPATH
python tools/demo_e2e.py --install            # 에뮬레이터 2대: 조용한 접근, 100m 앞 목록, 선점, 도착 시 확정, 자리 없음 취소, 먼저 주차, 버튼 한 번 주차, 오탐 차단 (51개 검사)
python tools/policy_e2e.py                    # 주행 중 화면, 공유 끄기, 동의 철회 후 재부팅, 201건 큐, 오디오 포커스 (20개 검사)
python tools/recovery_e2e.py                  # 전원 차단, 통신 불가, 부팅 중 출발 (16개 검사)
```

아래 세 개는 Linux 전용이며 디버그 빌드, `tools/emu.sh`로 켠 에뮬레이터, 8787 포트의 서버가 필요합니다. 통합 시험의 "앞차"와 "먼저 주차한 차"는 스크립트가 서버에 보내는 이벤트이고 에뮬레이터가 아닙니다.
